零、一分钟现状（先看这里）
----------------------------------------------------------------
一句话：这是一个“窗口捕获 + OCR + 争渡朗读 + 物理键盘”的《欢乐斗地主》无障碍助手原型。
它已经能：自动用电脑上已登录的 QQ 进大厅、自动点开欢乐斗地主、把画面文字读成可访问列表、
在真实牌桌上识别本人手牌点数花色、在用户明确要求下单次点击游戏里的按钮/手牌。

但必须诚实地说明：**它现在还不能让盲人用户用争渡和物理键盘完整地独立打完一局。**
出牌、过牌、叫地主/抢地主虽然有代码和部分现场验证，仍未做跨局、真人读屏验收；
最新的“游戏前台键盘模式”（第二节第九节）已经写好并编译通过，但**一次真机验证都还没做**，
也**没有打进安装包**。当前电脑上装着的版本比源码旧。

如果只看一件事：**先读第五节的目录、第六节的构建命令、第十七节的下一步优先级。**

二、产品目标、用户与硬性边界
----------------------------------------------------------------
产品：独立的 Windows 辅助软件。最低实测系统 Windows 10 IoT 企业版 LTSC 19044 x64。
用户：盲人。读屏为争渡（ZDSR），兼顾标准 UI Automation；只用物理键盘，不碰鼠标。

硬性边界（来自 docs\需求与边界.md，任何新功能都不能越线）：
1. 只读用户可见画面。**不读游戏内存、不读网络封包、不读隐藏牌**。
2. **不替用户做策略决策**：不自动叫地主、不自动选牌、不自动出牌。
3. 购买、充值、道具消耗、收费页面**默认不接管**。
4. 版本、布局、焦点、画面质量、牌面、阶段中任何一项不确定，就**停止游戏输入**。
5. 截图默认不留存；诊断日志不得包含密码、验证码、登录令牌。
6. 辅助软件自身的界面必须是标准可访问控件（有名称/角色/状态/值），不能用 OCR 或模拟鼠标代替。
   注意：游戏本体实测 UIA 为单个 Pane、Raw View 子节点 0、Win32 子窗口 0、MSAA accChildCount 0，
   所以对外部游戏画面只能用“窗口捕获 + 视觉识别”，这是本项目的特例，**不能宣称游戏原生无障碍**。

完整验收标准（还没达到）：盲人用户从已登录状态，用争渡和物理键盘**独立完成至少 20 局不同牌况**，
首次登录单独再测一次。没有真人读屏测试时，只能写“代码级检查通过，真人读屏未验证”。

六、构建 / 打包 / 安装 / 运行（命令级，照抄即可）
----------------------------------------------------------------
【构建（发布自包含单文件 exe）】
  & 'C:\Program Files\dotnet\dotnet.exe' publish `
      'D:\HappyDDZAccessibility\src\HappyDDZ.Assistant\HappyDDZ.Assistant.csproj' `
      -c Release -r win-x64 --self-contained true /p:PublishSingleFile=true `
      -o 'D:\HappyDDZAccessibility\release\app' --nologo
  只做语法检查（更快）：把上面的 publish 换成 build -c Release -t:Rebuild --nologo。
  官方脚本 tools\Build-Release.ps1 会先跑 native\build.ps1（需要 MSVC，路径见该文件）再 publish。

【打安装包】
  powershell -NoProfile -ExecutionPolicy Bypass -File tools\Build-Package.ps1
  产物：release\packages\HappyDDZ-<yyyyMMdd-HHmmss>\ 与同名 .zip，内含 Install.cmd、Install.ps1、
        HappyDDZ.Assistant.exe、native\bin\WindowCapture.exe、vendor\RapidV6\（同上子集）、models\、
        files.json（逐文件 SHA256）、安装与使用.txt。

【安装（用户侧）】
  解压 zip → 运行 Install.cmd（不需要管理员）→ 安装到 %LOCALAPPDATA%\HappyDDZAccessibility，
  并在桌面和开始菜单创建“欢乐斗地主无障碍助手”快捷方式；不会覆盖用户的 config 设置。
  重复安装前必须先关闭助手（脚本会检测并拒绝）。

七、用户操作说明（键盘全路径）
----------------------------------------------------------------
启动：桌面“欢乐斗地主无障碍助手”（或开始菜单同名项）→ 默认自动用电脑上已登录的 QQ 进大厅、
      再自动进入斗地主（见第八节）。不需要用户碰鼠标。
助手面板内：
  Ctrl+Alt+D          显示 / 隐藏助手面板（助手不在 Alt+Tab 里，游戏窗口保留在 Alt+Tab）
  Ctrl+Tab            在“当前局面 / 手牌 / 事件 / 设置 / 帮助”5 个选项卡之间切换
  Tab / Shift+Tab     在控件间移动
  方向键              在“当前画面公开文字”列表里逐项浏览（OCR 文字 + 中心坐标 + 是否可点击）
  Ctrl+F              按文字筛选列表
  回车                激活列表中“已核对可点击”的那一项（程序内部转换成对游戏的一次点击）
  F6 / “重读操作结果” 重读上一次结果
手牌页：
  左 / 右             按点数逐张浏览本人手牌
  Home / End          跳到首张 / 末张
  上 / 下             默认只做“本地拿放预览”；勾选“上下键操作游戏单张（实验）”后才操作游戏内单张
  Ctrl+上 / Ctrl+下   拾起当前点数整组 / 放下全部已抬起牌（实验，仅本地点按，游戏内未验证）
  回车                请求出牌（需用户自己先在游戏里选好牌，且门槛全通过才发一次点击）
  Ctrl+回车           请求过牌（本人“不出”门槛通过才发一次点击）
  还有一个“停止整组操作（Escape）”按钮，可中断后续逐张点击。
场次确认：选场次后助手主窗口内显示底分/豆子范围/风险说明，**默认焦点在“取消”**，
  Esc 取消，也可用“确认进入场次(&Y) / 取消进入场次(&N)”（UIA AccessKey 为 Alt+Y / Alt+N）。
  ★ 真钱入口、收费弹窗、未知弹窗一律只读。

  d. 任何一步复核失败 → 报告并停止，**不重试、不自动选场次、不自动消耗豆子**。

九、“游戏前台键盘模式”（最新源码的核心，未验证）
----------------------------------------------------------------
代码：GlobalKeyboardHook.cs（WH_KEYBOARD_LL 钩子）+ MainForm.cs 的 StartPlayMode / StopPlayMode /
      PollPlayModeAsync / HandleGlobalKeyboard / HandlePlayModeKeyAsync / AnnouncePlayState。
行为：StartPlayMode 会安装全局键盘钩子、启动 1.8 s 一次的只读后台扫描、播报当前牌桌状态，
      然后隐藏助手面板并把游戏窗口置前。
      钩子**只在游戏窗口是前台窗口时**才拦截，且只截 左/右/上/下/回车/F2，其他键一律放行；
      Alt/Shift 组合键放行（Ctrl 参与 Ctrl+上/下/回车 的语义）。
      拦截后：左/右 朗读当前手牌；上/下 拿放单张（走原来的 ToggleGameCardAsync 全套门槛）；
      Ctrl+上/Ctrl+下 整组；回车 出牌、Ctrl+回车 过牌；F2 重读牌桌状态。
      游戏窗口关闭或变化 → 自动 StopPlayMode 并把助手显示回来。
播报：AnnouncePlayState 播报场景、手牌张数、是否轮到你出牌/不出、剩余秒数、按钮是否已核对，
      并把可见的“底牌/上家/下家/轮到/剩余”文字一起读出来（这些是 OCR 到的原文，不是结构化牌局状态）。
★ 现状：编译通过（2026-10-04 01:15，0 警告 0 错误），**未做过任何真机验证**；
  没有验证过：钩子是否真的能在游戏前台拿到方向键、助手隐藏后焦点行为、
  后台 1.8 s 扫描与出牌的时序是否够快、争渡是否会念出来。

十、安全确认模型（所有游戏动作共用，改动前务必先读懂 ReadOnlyScanner.cs）
----------------------------------------------------------------
1. 两帧一致：几乎所有判定都要“相隔约 180 ms 的两帧画面都成立”，单帧一律不采信。
2. 场景 + 版本 + 尺寸：必须是已知场景（牌桌/叫地主阶段/对局回放/指定弹窗…）、
   已知客户端尺寸（牌桌 1280×720、大厅 1280×860、登录窗 318×432），否则拒绝。
3. 新鲜度：完整扫描结果超过 5 秒（快速刷新是 60 秒）就不再可用。
4. 临点击复核：发送点击前再抓两帧复查（文字/位置/按钮像素/钟面/底栏），任何一步变化就取消。
5. 只点一次：所有点击都是“用户明确要求 + 门槛通过 → 单次点击”，**失败不自动重试**。
6. 点击后回读：点击后重新扫描并比对（张数、抬牌集合、按钮是否消失…），
   拿不到确定结果就如实报告“已发送但未确认”，绝不假装成功。
7. 绝不自动：不自动选牌、不自动出牌策略、不自动进收费页、不自动领奖（唯一例外见第三节：图形 X 关闭弹窗已明确改名“领取并关闭”，曾误领 1000 限时钻石）。
8. 遮罩防护：托管暗色遮罩、抬牌、动画、牌数变化、未知牌、18/19 张不支持的布局，一律清空候选或拒绝动作。
9. 键盘模式同样受这套门槛约束：钩子只负责“把按键变成一次受控请求”，不绕过任何复核。

十一、已识别的场景与可点击目标（ReadOnlyScanner 的确认标志）
----------------------------------------------------------------
ScanResult 里的确认标志（都为双帧通过后才会 true）：
  CancelTrustConfirmed（取消托管）、SettlementContinueConfirmed（继续游戏）、

  OwnBidButtonsConfirmed（本人叫地主/不叫）、OwnRobButtonsConfirmed（本人抢地主/不抢）、
  BadLuckCloseX（换玩法建议）、ShareResultCloseX（战绩分享遮挡）、
  PiggyBankCloseX（猪猪储豆罐收费弹窗关闭）、
  BeanAidConfirmConfirmed / BeanAidCloseX（送你欢乐豆补助“确定”/关闭）、
  RoomExitConfirmed（退出当前场次）、OwnPassConfirmed（本人不出）、OwnPlayConfirmed（本人出牌）、

  PackCloseX / ReplayControls / SeasonCloseX / SeasonRefreshCloseX / BattleGuideCloseX、
  OwnTurnSeconds（本人钟面秒数）。

其余一律“仅供阅读”。收费页、未知弹窗、出牌/过牌/抢地主在门槛不成立时全部保持禁用。

十二、识别能力与实测数据（诚实口径，不要拔高）
----------------------------------------------------------------
A. 手牌点数与花色（CardCandidateReader + models\cards\replay-plus-live-one-hand.json）
   - 方法：牌角图形模板匹配。两帧位置与张数必须稳定；未知一律显示“未知”。
   - 方法限制：模板只来自“一局历史回放 + 一手实局”，同一客户端皮肤、1280×720。
   - 实测（2026-10-04 重跑 --evaluate）：8 手 / 142 张，完整候选 142/142，已知字段错误 0。
     ★ 但其中 match-01-start 是模板的训练来源，真正的“留出”只有 7 手 125 张；
     ★ 这是静态图重复输入当双帧，**不是**实时双帧、跨皮肤、20 局的准确率。
   - 已知失败模式：托管暗色遮罩曾把普通牌误报“小王”（已加整行亮度门槛拒绝）；
     大小王、重叠牌、18/19 张、多张抬起后回读仍不稳。
B. 本人钟面（TimerCandidateReader + models\timer\clock-v1.json）
   - 只读播报 4~20 秒候选，两帧钟面形状与数字必须一致；实机扫描到过 9/6/18/15/8 秒。
   - 离线覆盖 20~4 秒序列、独立样本 19/6/11 秒；**不能**据此判定出牌时限。
C. 叫地主/抢地主阶段（BidPhaseReader + models\controls\bid-phase-v1.json）
   - 模型只含两种按钮文字区域的二值图形掩码，不含私密全图或身份信息。
   - 叫地主：现场点击过并拿到地主标识；抢地主：只有离线正负样本，真机未触发。
D. OCR 基础：RapidV6（RapidOCR v3.9.2 的 ONNX 模型），默认 CPU + tiny+tiny。
   大厅单帧约 755 ms、双帧约 1.7 s；牌桌快速刷新（只做牌角模板，跳过整屏 OCR）约 0.8~1.0 s。
