# 需求与边界

依据：用户在 2026-10-02 会话中提供的《欢乐斗地主》Windows 无障碍辅助软件开发计划，完整原文保存在 `RapidV6_OCR/欢乐斗地主无障碍开发计划.md`；以及项目内 `docs/无障碍开发总规范-基线.md`（复制自 `C:\无障碍开发总规范.md`）。以下内容用于下次会话脱离聊天记录继续开发。原始计划中 `D:\RapidV6_OCR` 路径是移动前的历史位置。

## 产品与环境

- 产品：独立的 Windows 辅助软件；最低实测系统 Windows 10 IoT 企业版 LTSC 19044 x64。
- 主要用户：盲人；读屏为争渡，兼顾标准 UI Automation 读屏；物理键盘输入。
- 游戏：QQ 游戏大厅 `D:\HappyDDZ\GameNew\HLDDZ3D.exe`，采样版本 8.057.106.17343；已登录 QQ 作为当前测试起点。
- 辅助软件自身必须使用标准可访问控件，提供名称、角色、状态、值与事件；不能用 OCR 或模拟鼠标代替自身的无障碍接口。
- 外部游戏实测 UIA 为单个 Pane、无子控件；对外部画面采用窗口捕获与视觉识别是本项目特例。不能称游戏原生无障碍。

## 用户核心路径

1. 启动辅助软件，得知未连接/已连接；使用 Tab 到“连接游戏”并按 Enter。
2. 在辅助程序中选择普通斗地主与场次；朗读规则及可能花费，收费或未知内容不得自动进入。
3. 随时查询本人身份、轮次、倒计时、三人剩余张数、上轮牌型与出牌者；不确定时读“不确定”及上次确认时间。
4. 方向键逐张或按点数浏览手牌，Space 切换选择；每张牌读顺序、点数、花色、选中状态。
5. 用户决定出牌、过牌、叫地主；程序仅在目标、轮次、牌面和窗口新鲜度均验证后单次提交，随后回读结果；失败不自动重试。
6. 对手出牌与结算可听、可从事件记录回看；异常弹窗与登录验证码必须有明确可退出路径。

## 输入与公平性

只读用户可见信息；不得读取游戏内存、网络封包、隐藏牌或代用户做策略决策。所有购买、充值、道具消耗和收费按钮默认不接管。若游戏版本、布局、窗口焦点、帧质量、牌面或阶段不确定，停止游戏输入。截图默认不留存；诊断日志不得包含密码、验证码和登录令牌。

## 阶段门槛

0. 现场摸底：采集大厅、模式、场次、真实牌桌、倒计时、结算、弹窗；核对 UIA、键盘、读屏、捕获、成本。先得出可行性和阻断点。
1. 可访问壳程序：主窗口、手牌、事件、设置与帮助的完整键盘/UIA 路径；争渡真人验证。
2. 只读牌局助手：真实画面采集，OCR 加牌图识别，有限状态机与时序校验；用独立标注集评估准确率和延迟。
3. 用户控制动作：仅在可靠识别和合法阶段下，出牌、过牌、叫地主及安全弹窗；真实对局中零未确认点击。
4. 稳定覆盖与发布：窗口变化、断线、更新、弹窗、安装/卸载/回滚；交付源码、模型许可、帮助、测试矩阵与限制。

完整验收：盲人用户从已登录状态用争渡和物理键盘独立完成至少 20 局不同牌况，首次登录另测。没有真人读屏测试时必须明确“代码级检查通过，真人读屏未验证”。
