# 阶段 0 现场报告

日期：2026-10-02；09:05 补充大厅与导航实测。本报告是现场摸底，不能视为完成 20 局验收。

## 已观察事实

- 本机 Windows 10 IoT 企业版 LTSC 19044 x64；`.NET 10.0.302` SDK 和 10.0.10 桌面运行时已安装；`dotnet` 不在 PATH，脚本使用完整路径。
- 游戏 `HLDDZ3D.exe` 正在运行，画面绘制的标题含版本 8.057.106.17343；Win32 窗口标题仅为“欢乐斗地主”。本次 UIA 复核：根控件为 Pane，子元素 0 个。
- 初始画面为设置→音效。退出后出现促销弹窗及充值页；手动关闭弹窗并返回大厅，观察到“斗地主合集”。
- 斗地主合集有“经典斗地主”“不洗牌斗地主”“欢乐经典”等模式。经典斗地主场次页显示新手场底分 20、初级场 80、普通场 300 等；这些场次涉及金币，未进入。
- 经典斗地主页有“排位模式 免费玩”入口。进入“技能排位”后，生命值从 25/25 降至 24/25，金币显示仍约 1.888 万，钻石 0。匹配后进入真实三人排位经典局。此入口**消耗生命值**，不能称零资源成本；本次仅进行一次采样。
- 牌桌为 1280×720 客户区：17 张重叠手牌，左、右玩家剩余数，叫地主阶段的“抢地主/不抢”，本人回合的“出牌/不出/提示”，倒计时，地主标识，对手打出的牌和英雄卡遮挡。未选择牌或代用户做出牌决定。超时后游戏自行处理，最终观察到“胜利”结算、总分 1060，随后出现“太久没操作，地主要请你离开房间了”弹窗。不能把这次自动结果计为独立对局测试。
- 前台屏幕区域截图能取得画面；`PrintWindow` 返回黑帧。自行编译的 Windows Graphics Capture 组件可按游戏窗口抓取 1280×720 客户区，辅助程序遮挡游戏时仍可抓取；游戏最小化时明确返回失败并在测试后恢复。
- RapidV6 版本 2026-10-01、tiny 检测加 tiny 识别、真实牌桌整图：CPU 3 次中位 319.5 ms，DirectML 3 次中位 1528.0 ms。整图 OCR 能读出“出牌/不出/提示”和部分计数，不能正确读取整手牌。17 个牌角单独放大后，仅 8 个 OCR 字符串与人工预标注点数完全一致；花色没有可靠输出。此为一手牌，不能当独立准确率数据集。

## 当前阻断点

1. 手牌牌角重叠，整图 OCR 对 17 张牌基本失效。单张放大 OCR 仍会混淆牌值与花色；只有一手样本，无法评估泛化。阶段 3 输入因此禁用。
2. 游戏自带倒计时很短，真实局面、状态转换、英雄卡遮挡、其他牌型和收费规则都未充分采样。
3. 游戏没有 UIA 子控件；游戏自身键盘控制和争渡输出未做真人测试。
4. 首次登录、验证码、好友房与其他模式尚未验证；QQ 大厅已验证从已登录状态读取和选择欢乐斗地主入口，但大厅自身 UIA 信息很少。
5. 排位免费标识不等于不消耗游戏资源。继续采集真实局面前应查明可重复、可控的样本获取方法。

## 样本与隐私

原始画面与 OCR 结果放在 `samples/private/`，可能含玩家昵称、头像、聊天文字，不进入发布目录。`samples/anonymous/` 有手牌/17 个牌角，以及模式网格、场次网格、动作按钮、结算面板和超时弹窗的裁切图；已避开玩家头像与昵称。截图留存设置在辅助程序中默认关闭。

## 可行性结论

按窗口捕获、RapidV6 调用和标准 WinForms UIA 路线已在本机验证可运行；牌面可靠识别与真人读屏操作尚未达到继续开放动作层的门槛。后续应优先构建独立标注集，评估整手牌完全正确率、倒计时延迟与未知状态处理。
